# MERIDIAN — ニュースレター作成ツール

> 🇬🇧 [English version](README.md)

> **MERIDIAN** — *Where medicine meets the world.*

**名古屋大学大学院医学系研究科**ニュースレターのための公式作成ツールです。

## なぜこのツールが必要なのか

従来のやり方で部局のニュースレターを作るのは、編集者が Word の下書きから段落をコピーして Outlook に貼り付け、書式が崩れていくのを見守り、写真を手動でファイル共有にアップロードし、受信者には**途中で切れた / レイアウトが崩れた / 画像アイコンが壊れた**メールが届く——号ごとに半日が「中身づくり」ではなく「配管作業」で消える、というものでした。

**MERIDIAN はその作業をダブルクリック1回に置き換えます。** 編集者は Word のテンプレートにいつも通りに記事を書き込むだけ。ランチャーがそれを読み取り、Outlook / Gmail / Apple Mail で同じように見える綺麗な HTML メールを構築し、写真を公開ウェブアドレスにアップロードし、本文入り + BCC 入力済みの Outlook 下書きを開きます。あとは宛先を入力（または保存済みリストを読み込み）してプレビューを確認、「送信」をクリック。**毎号、数分で完了。**

## このツールでできること

- **Word ファイル → 洗練されたメール、貼り付け作業ゼロ。** 「なんで全部 Times New Roman になってるの?」もありません。Word テンプレートには名古屋大学公式デザインシステム（NU ブルー `#003F88`、ウォームゴールドのアクセント、見出しは Cambria、本文は Calibri）が事前に適用されており、HTML 出力は同じ見た目を — 各メールクライアントの制約の範囲内で — 忠実に再現します。
- **本物の Outlook 下書き、`mailto:` リンクではありません。** Windows ではツールが Outlook デスクトップに直接対話して `multipart/alternative`（HTML + 平文）の下書きを生成します — 企業のスパムフィルタでスコアが良く、編集者は何も貼り付ける必要がありません。macOS では Apple Mail（または既定のメールクライアント）が開き、本文がクリップボードに入った状態で貼り付けるだけ。
- **写真も自動処理。** Word ファイルに画像を貼り付けるだけで、ツールが抽出 / リネーム / GitHub アップロード / メール内 URL 書き換えまで実行します。受信者には「リモートコンテンツを表示するにはクリック」のプレースホルダではなく、本物の写真がそのまま表示されます。一括で渡したい場合は `drop-images/` フォルダに番号付きファイル名で投入すれば、適切なセクションに自動的に配置されます。
- **複数メールクライアントを最初から想定した設計。** 600 px のテーブルレイアウト、すべての CSS を inline 化、Outlook 用 ghost-table（カラム保持）、1 px 金色罫線のための mso-line-height ロック、印刷時はクリーム色 + 金色のマストヘッドをインク節約の白黒版に切り替える印刷専用スタイルシート。Outlook 2016+、Outlook web、Gmail web/モバイル、Apple Mail macOS/iOS で動作確認済み。
- **送信前にチェック。** マストヘッドに `VOL. XX` が残ったままの下書きは絶対に送れません — バリデータがプレースホルダ未入力をハードブロックします。件名が長すぎて受信者の受信トレイで切れる前の警告。画像リンク切れの監査。Gmail 102 KB クリッピング警告。同僚から「あれ、画像が出ないんだけど…」と指摘される前にツール側で気付かせます。
- **日英バイリンガル。** README、ランチャーの対話、エラーメッセージ、すべてが日本語と英語で提供されています。macOS では言語環境を自動検出。
- **プログラミング不要。** 編集者は `Make Newsletter.bat`（Windows）または `Make Newsletter.command`（macOS）をダブルクリックするだけ。質問は2つだけ：号数と Word ファイル名。それで完了です。

## 想定ユーザー

主に大学院医学系研究科の四半期ニュースレターを担当する編集者向けですが、ツールは**自由にフォーク可能**です。同じ課題を持つ他の機関なら、`scripts/config.py` のロゴ + 学部長写真 + カラーパレットを差し替え、自分の GitHub リポジトリを指定すれば、半日で自部局のブランドに合わせたニュースレターパイプラインが完成します。

## 内部構成（開発者向け）

Python 3.12、`python-docx`、`Jinja2`、`css_inline`（Rust 製）、`BeautifulSoup4`、`click`、`pytest`。Outlook 連携は Windows で `pywin32` COM、macOS で AppleScript / `osascript`、Linux で `xclip` / `wl-copy`。パーサ、画像ハンドラ、バリデータ、平文コンバータ、メールバックエンド、セキュリティガード（受信者検証時の NFKC + 不可視文字除去、CSS-hidden 要素のスクラブ、URL スキーム allowlist）、ビジュアル回帰契約をカバーする **21 ファイル・201 件のテスト**。アーキテクト / Python / セキュリティ / コード / ビジュアル / UX / メール到達性の **10 ラウンドのレビューと 29 個の修正バンドル** — すべての変更に最低1つの回帰テストが付随しています。本番タグは `v1.0.1-bundle29`。

編集者として使う場合、上記の内容を理解する必要は**ありません**。以下の4つのセットアップステップだけで十分です。

## セットアップ — 1回だけ実施 (約15分)

**4つのステップを順番に**実施してください。スキップしないでください。

### ステップ 1 — 無料の GitHub アカウントを作成

1. <https://github.com/signup> にアクセスします。
2. ユーザー名、メールアドレス、パスワードを入力してサインアップを完了します。
3. **作成した GitHub ユーザー名**をツール管理者に送ってください。写真をアップロードするための書き込み権限が付与されます。管理者は通常**1営業日以内**に確認します。**確認が来るまでステップ 2 に進めません。**

> **GitHub とは?** ツールの保管場所です。あなたのアカウントには、ニュースレターの写真をアップロードする権限が与えられます。GitHub の使い方を覚える必要はありません — ツールがすべて自動で処理します。

> **病院の PC で、ソフトウェアのインストールが制限されている場合:** 以下のステップ 2 と 4 では、GitHub Desktop と Python のインストールに管理者権限が必要です。お使いの PC で IT 部門の制限がある場合は、**この README を IT 部門に見せて**、代わりにインストールを依頼してください。このセクションを見せれば、必要な要件がすぐに分かります。

### ステップ 2 — GitHub Desktop をインストール

1. <https://desktop.github.com> にアクセスし、**Download for Windows** (または **macOS**) をクリック。
2. インストーラーを実行してください。デフォルト設定で問題ありません。
3. GitHub Desktop が起動したら **Sign in to GitHub.com** をクリック。ブラウザが開き GitHub Desktop の認証を求められます。**Authorize** をクリックしてください。ブラウザは自動的に GitHub Desktop に制御を戻します — その画面に戻ってください。

### ステップ 3 — ツールをダウンロード (クローン)

1. GitHub Desktop のメニューから **File → Clone repository…** をクリック。
2. **URL** タブをクリックし、以下のアドレスを貼り付けます:
   ```
   https://github.com/BasileChretien/Newsletter-graduate-school-medicine.git
   ```
3. **Local path** で **Choose…** をクリックし、**ドキュメント** (または覚えやすい場所) を選びます。
4. **Clone** をクリック。数秒後に PC に `Newsletter-graduate-school-medicine` というフォルダができます。**毎号このフォルダを使います。**

> **次回 github.com を見るときの注意:** GitHub のページには緑色の **Code** ボタンから **Download ZIP** を選べる項目があります。**使わないでください** — ZIP からは写真のアップロード機能が使えず、受信者には**画像が壊れたアイコン**が表示されてしまいます。必ず **GitHub Desktop**（このステップ 3 の手順）から取得してください。間違って ZIP を展開した場合も、ランチャーが自動で検知して停止し、正しい手順を案内するので安心です。ただ、最初からこの方法を選んでおけば「あれ、なぜ動かない?」と数分悩む手間が省けます。

### ステップ 4 — Python をインストール

Python はツールを動作させるプログラムです。

- **Windows:** <https://www.python.org/downloads/> からインストーラーをダウンロードし、実行してください。**重要:** 最初の画面で **「Add Python to PATH」**のチェックを入れてから *Install Now* をクリックしてください。
- **macOS:** **ターミナル** (アプリケーション → ユーティリティ → ターミナル) を開き、`python3 --version` と入力して Enter キーを押します。`3.12.x` のようなバージョン番号が表示されたら完了です。表示されない場合は Windows と同じ手順で <https://www.python.org/downloads/> からインストールしてください。

これでセットアップは完了です。**この4つのステップを再度行う必要は二度とありません。**

## ニュースレターの作り方 (毎号の手順)

### ステップ1 — Wordでテンプレートを開いて正しい名前で保存

`Meridian_Newsletter_Template.docx` をダブルクリックします。Wordが開きます。**ファイル → 名前を付けて保存**を使い、`Make Newsletter.bat` と同じフォルダに**コピー**を保存してください。

> ⚠️ **ファイル名は重要です。** 必ず以下の形式で保存してください:
>
> ```
> issue-N.docx
> ```
>
> `N` は号数です — 第3号なら **`issue-3.docx`**、第12号なら **`issue-12.docx`**。

このパターンに従えば、ステップ4のランチャーが**ファイル名を自動入力**してくれます。Enterキーを押すだけで済みます。

### ステップ2 — 内容を入力

保存したファイルで:

- マスト見出しの **発行情報** ("VOL. XX | ISSUE NO. XX | MONTH YEAR") を実際の巻号と月年に置き換えます。
- **`[Author(s)]`**, **`[Paper Title]`**, **`[Visitor Name]`**, **`[YYYY/MM/DD]`**, **`[Country]`** などの角括弧で囲まれたプレースホルダーを実際のテキストに置き換えます。
- グレーの「Lorem ipsum」風の段落を実際のニュースレター内容に置き換えます。
- **セクションは自由に編集できます。** ツールは7セクションのテンプレートで配布されますが、号ごとに名前の変更、追加、削除、並び替えができます。
  - **セクション名を変える:** Word で見出しの文字を編集するだけ。番号はそのままで構いません。
  - **新しいセクションを追加:** 追加したい場所の空行にカーソルを置き、次の番号、ピリオド、半角スペース、タイトルの順で入力 — 例 `8. Special Feature: Nobel Prize Winner`。(コロン `8:` も使えます。`第8章 — タイトル` 形式も認識されます。) その行を選択し、*ホーム → スタイル*の**見出し 1** をクリック (または Windows: *Ctrl+Alt+1* / Mac: *⌘+Option+1*)。
  - **セクションを削除:** 見出しと、その下にあるそのセクションの全内容 (段落、箇条書き、表) を選択して **Delete** キー。
  - **サブ見出し** (例「Notable Publications」) は Word の**見出し 2** スタイルを使ってください: 行を選択して *ホーム → スタイル* の**見出し 2** をクリック (または *Ctrl+Alt+2* / *⌘+Option+2*)。スタイルを忘れても、ピリオドのない短い太字の1行であれば自動で認識されます。

> **テンプレートを壊す心配は不要です。** あなたが作る `issue-3.docx` はコピーであり、元の `Meridian_Newsletter_Template.docx` が変更されることはありません。**コピーが壊れたと思ったら、削除してテンプレートをもう一度開いてください。** 何も失われません。

> **学長のお名前と写真は既に入力されています** (現在は *勝野雅央先生*)。学長が変わった場合は、メンテナーに依頼してテンプレートを更新してください。

完了したら保存します。

### ステップ3 — 写真を追加 (任意)

> ⚠️ **プライバシーに関する注意:** ニュースレターに追加した写真はすべて**公開**の GitHub URL (`raw.githubusercontent.com/...`) にアップロードされ、永久に残ります。**患者の写真、同意のない顔写真、その他公開ウェブページに掲載できないものは絶対に貼り付けないでください。**

**写真は Word ファイルに直接貼り付け**ます。表示したい場所にカーソルを置いて → **挿入 → 画像** → ファイルを選択 → 角をドラッグしてサイズ調整。これだけです。ツールが自動的に検出して、メールの同じ位置に同じサイズで配置します。

**コツ:**

- メールでの表示サイズに近い大きさに Word でリサイズしてください (正確でなくて構いません — ツールが大きすぎる画像をメールに収まるように自動で縮小します)。
- 大きすぎる場合は、Word で角を内側にドラッグしてください。
- どのセクションにも、好きなだけ写真を追加できます。

> **学長の写真と学校のロゴはすでに組み込まれています。** 自分で追加する必要はありません。

> 上級者向け: バッチで複数の写真を追加するには、`drop-images/` フォルダにファイル名規則 (`s<セクション番号>_<順番>_<スラッグ>.jpg`) で配置する方法もあります。ほとんどの編集者には不要です — Word に貼り付ける方が早いです。

### ステップ4 — ランチャーをダブルクリック

プロジェクトフォルダ内の以下のファイルを**ダブルクリック**します:

- **Windows:** `Make Newsletter.bat`
- **macOS:** `Make Newsletter.command`

小さな黒いウィンドウが開き、2つの質問が表示されます:

```
Issue number / 号数 (例 3): 3
Word file / Wordファイル [issue-3.docx]:        ← Enterキーを押すだけ
```

`3` (または該当する号数) を入力してEnterキーを2回押してください。初回のみ、ツールが自動でセットアップします (約1分)。次回以降はすぐにメール作成が始まります。

### ステップ5 — 宛先を選んで送信

完了すると、いつものメールアプリにニュースレター入りの下書きが表示されます。

- **Outlookデスクトップの場合:** 下書きが開きます。**To: 欄に宛先を入力して「送信」をクリックするだけです。**
- **その他のメールアプリの場合:** クリップボードにニュースレターがコピーされ、新しい下書きが開きます。本文をクリックして `Ctrl+V` (Mac は `⌘+V`) で貼り付け、宛先を入力して送信します。

> **重要:** メールは自動送信されません。**ご自身で「送信」ボタンを押す必要があります。**

### 宛先を保存しておく (任意)

毎号同じ50人くらいに送るなら、`recipients.example.txt` を `recipients.txt` にコピーして、メールアドレスを1行に1つ書いておきます。次回以降は Outlook の BCC 欄が自動で埋められます。`recipients.txt` はあなたのコンピュータにのみ保存され、GitHubには公開されません。

## よくある質問

**❓ ランチャーをダブルクリックしても何も起きない / 一瞬で閉じる**
原因は通常2つです:
- **Pythonが未インストール:** コマンドウィンドウからランチャーを実行するとエラーが読めます。プロジェクトフォルダを開き、アドレスバーに `cmd` と入力して Enter、その後 `"Make Newsletter.bat"` と入力して Enter。Python についてのエラーが出たら、Python をインストールしてください (セットアップ手順2)。
- **macOSのみ:** ターミナルでフォルダに移動し、`chmod +x "Make Newsletter.command"` を一度実行してください。再度ダブルクリックすれば動作します。

**❓ 学部長の写真や学校のロゴがプレビューに表示されません**
ランチャー（または `all` コマンド一式）を使ってください — その手順で写真もウェブにアップロードされます。それでも表示されない場合は、ブラウザの再読み込みをお試しください。

**❓ 「ERROR: file not found」と表示される**
入力したWordファイルがプロジェクトフォルダ内にありません。`issue-3.docx` (またはあなたが付けた名前) を `Make Newsletter.bat` と同じフォルダに移動してから、ランチャーをもう一度実行してください。

**❓ プレビューに画像の代わりに壊れたアイコンが表示される**
写真がまだ公開Webにアップロードされていない可能性が高いです。ランチャーをもう一度実行してください (毎回写真は自動でアップロードされます)。プレビューを更新してください。`drop-images/` フォルダを使った場合は、ファイル名のパターン `s<section>_<order>_<slug>.jpg` に合っているか確認してください (例: `s3_01_lab.jpg`、❌ `S3-01-lab.jpg` や `lab photo.jpg` は不可)。

**❓ もう一度作り直したい**
ランチャーをもう一度ダブルクリックして同じ号数を入力してください。前回の出力は上書きされます。問題ありません。

**❓ テンプレートの色 / フォント / タイトルを変えたい**
これらは号ごとに統一感を保つため意図的に固定されています。デザイン変更が必要な場合は、開発者 (またはこのツールをセットアップした担当者) にご相談ください。

**❓ 新しいセクションを追加したい**
できます — Word で追加したい場所にカーソルを置き、次の番号、ピリオド、タイトルの順で入力してください (例: `8. Special Feature: Nobel Prize`)。その行を選択し、*ホーム → スタイル* の**見出し 1** をクリック (または *Ctrl+Alt+1* / *⌘+Option+1*)。コードの修正は不要です。

**❓ セクションやサブ見出しを削除したい**
見出しと、その下にあるそのセクションの全内容 (段落、箇条書き、表) を選択して **Delete** キーを押してください。ツールは削除されたセクションをそのままスキップします。

**❓ テンプレートを壊してしまわないか不安です**
心配無用です — あなたの `issue-3.docx` はコピーで、元の `Meridian_Newsletter_Template.docx` は変更されません。**コピーが壊れたら、削除してテンプレートをもう一度開いてください。** 何も失われません。

**❓ メールファイルはどこに保存されますか?**
`dist/` フォルダの中です。第3号なら `dist/issue-3.html` です。いつでもダブルクリックして開けます。

**❓ ドロップフォルダの写真はどこに行きますか?**
第N号なら `assets/issue-N/` に保存されます。GitHubにもアップロードされて、公開URLになります。

**❓ どのメールアプリが使われますか?**
お使いのコンピュータで `mailto:` リンクのデフォルトに設定されているアプリです。`python build_newsletter.py detect-mail` を実行すると、ツールが検出した結果が表示されます。
- Windows: 設定 → アプリ → 既定のアプリ → メール
- macOS: メールアプリ → 環境設定 → 一般 → デフォルトメールアプリ

**❓ デフォルトはOutlookなのに、ブラウザが開いてしまう**
Outlookが起動していない、または最近のOfficeアップデートで連携が変わった場合に起こります。回避策として `python build_newsletter.py all ... --backend default` を実行してください (Outlook以外と同じパス: クリップボードと空の下書きを使用します)。または、Outlookを先に開いてから再実行してください。

**❓ メールが開いたが、本文にニュースレターが入っていない (空白のメッセージ)**
Outlook以外のパスを使っています。ニュースレターはクリップボードにコピーされていますので、メッセージ本文をクリックして `Ctrl+V` (macOSは `⌘+V`) で貼り付けてください。

**❓ ランチャーが英語表示なのはなぜですか?**
`Make Newsletter.bat` は意図的に英語のみで記述しています。Windows の `cmd.exe` はバッチファイルを OEM コードページ (日本語環境では cp932) で読み込むため、UTF-8 で書かれた日本語文字が文字化けしてエラーの原因になります。日本語の編集ガイドはこの README.ja.md と Python 出力で提供しています。macOS の `Make Newsletter.command` は UTF-8 を正しく扱えるため、ローカライズ表示が利用できます。

**❓ 日本語の文字が四角 (□) になる (macOS の `Make Newsletter.command` で)**
ターミナルのプロファイル設定でフォントを **MS Gothic** などの日本語対応フォントに変更してください。

**❓ よくわからないエラーメッセージが出る**
赤い文字をすべてコピーして開発者に送ってください。ほとんどのエラーは何が悪いか明確に書かれています (例: 「画像のファイル名が規約に合っていません」)。

**❓ 受信者の一部から「メール内の写真が壊れている / 表示されない」と言われた**
写真は GitHub (開発者向けサービス) の `raw.githubusercontent.com` でホスティングされています。一部の企業 / 病院のメールフィルタは、メール本文は通すのに、このドメインからの画像だけを隔離 / 削除することがあります。名古屋大学の受信者でこの現象が報告された場合は、開発者に **GitHub Pages ミラー** を設定してもらってください — 同じファイルを `<ユーザ名>.github.io/<リポジトリ名>/assets/...` から配信できます (別のネットワーク経由なのでフィルタにかかりにくい)。それまでの暫定対策として、受信者は壊れた画像アイコンをクリックすれば直接表示できます。

**❓ BCC で何人まで一度に送れますか?**
名古屋大学を含むほとんどの大学では、1通のメールあたり **約 50 件の BCC** が上限です。これを超えると、メールサーバーが「一斉配信」とみなして遅延・隔離する場合があります。配信先がそれ以上ある場合は、`recipients.txt` を 50 件以下に分けて複数回送信してください (上限はメールサーバー側の制御で、ツール側では制限していません)。さらに大規模な配信が必要な場合は、IT 部門にメーリングリストアドレスの発行を相談してください。

**❓ 受信者の迷惑メールフィルタはこのメールを信頼してくれますか?**
送信元の信頼性は、ツールではなく**お使いの大学のメールサーバー**で決まります。`@med.nagoya-u.ac.jp` から送信していれば、大学の SPF / DKIM / DMARC 設定が自動的に効いているので追加の設定は不要です。個人の Gmail / Outlook から送ると、企業フィルタでスコアが悪化することがあります。

**❓ メールを印刷したら、ヘッダー (マストヘッド) の見た目が画面と違って見える**
これは意図的な動作です。印刷用スタイルシートが、画面表示の濃いクリーム色 + 金色のマストヘッドを、**カラーインクを使わない、シンプルな白黒版**に切り替えています。受信者がメールを読むときは画面表示のデザインのままで、印刷したコピーだけが見た目が違います。
