## 導入前と導入後

| 従来の手順 | MERIDIAN を導入した場合 |
|---|---|
| Word を開き、節ごとにコピーして Outlook に貼り付ける | Word をいつもどおりに記入し、`Make Newsletter.bat` をダブルクリック |
| Outlook 上で書式が崩れていくのを眺めるしかない | 書式を保持した HTML メールが Outlook の下書きとして開く |
| 写真を縮小して共有フォルダにアップロードし直す | Word に写真を貼り付けるだけで、ツールが自動でアップロード |
| 送信後に受信者側で画像が表示されないことに気付く | 送信前に画像のリンク切れ、容量超過、未入力プレースホルダを自動でチェック |
| 毎号 BCC リストを再入力する | `recipients.txt` から BCC を自動入力（区切り文字や見えない文字の混入も防止） |
| 号ごとに半日が付随作業に消える | 号ごとの所要時間は数分 |

> **動作を確認したい場合：** リポジトリをクローンし、`python build_newsletter.py build-template` を実行すると、サンプルテンプレートを Word で開けます。HTML 側は、任意の DOCX を埋めて `python build_newsletter.py build --input issue-1.docx --issue 1 --no-remote-check` で確認できます。

## 開発の経緯

従来、部局のニュースレター制作では、編集者が Word の下書きから段落を一つずつ Outlook にコピーし、崩れていく書式と格闘しながら、写真は手作業で共有フォルダにアップロードしていました。受信者側では、文章が途切れる、レイアウトが崩れる、画像が表示されない、といったメールが届きます。号ごとに半日が、本来の編集作業ではなく付随作業に費やされてきました。

**MERIDIAN は、この一連の作業をダブルクリック 1 回に集約します。** 編集者は Word のテンプレートにいつもどおりに記事を書き込むだけで、ランチャーが Word ファイルを読み取り、Outlook・Gmail・Apple Mail で同じように表示される HTML メールを生成し、画像を公開 URL にアップロードしたうえで、本文と BCC があらかじめ入力された Outlook の下書きを開きます。あとは宛先を入力（または保存済みリストを読み込み）し、内容を確認のうえ「送信」をクリックするだけ。1 号あたりの所要時間は数分です。

## このツールでできること

- **Word ファイルから、書式の整ったメールへ。** 貼り付け作業は発生しません。「気付いたら全文 Times New Roman になっていた」といった事故も起こりません。Word テンプレートには名古屋大学公式デザインシステム（NU ブルー `#003F88`、ウォームゴールドのアクセント、見出しは Cambria、本文は Calibri）が組み込まれており、HTML 出力も各メールクライアントの制約の範囲内で同じ見た目を再現します。
- **`mailto:` リンクではなく、本物の Outlook 下書きを生成。** Windows ではツールが Outlook デスクトップを直接操作し、`multipart/alternative`（HTML と平文）形式の下書きを生成します。企業のスパムフィルタでの評価も良好で、編集者は本文を貼り付ける手間がありません。macOS では Apple Mail（または既定のメールクライアント）が開き、本文がクリップボードに入った状態で貼り付けるだけです。
- **写真も自動処理。** Word に画像を貼り付けるだけで、抽出・リネーム・GitHub へのアップロード・メール内 URL の書き換えまでをツールが実行します。受信者側では「リモートコンテンツを表示するにはクリック」のような未読み込みアイコンではなく、本物の写真がそのまま表示されます。一括で渡したい場合は、`drop-images/` フォルダに番号付きファイル名で投入することも可能です。適切な節へ自動的に配置されます。
- **複数メールクライアントを前提に設計。** 600 px のテーブルレイアウト、すべての CSS の inline 化、Outlook 用 ghost-table によるカラム保持、1 px 金色罫線のための mso-line-height ロック、印刷時にはカラーインクを使わない簡素な白黒モードへ自動的に切り替わります。Outlook 2016 以降、Outlook web、Gmail（web・モバイル）、Apple Mail（macOS・iOS）で動作確認済みです。
- **送信前のチェック機構。** 題字部に `VOL. XX` のような未入力プレースホルダが残ったままの下書きは、送信前に検出され処理が中断されます。件名が長すぎて受信トレイで切れてしまう前の警告、画像のリンク切れの確認、Gmail の 102 KB 自動省略への警告も組み込まれています。同僚から画像表示の不具合を指摘される前に、ツール側が事前に検出します。
- **日英対応。** README、ランチャーの画面、エラーメッセージは、いずれも日本語と英語の両方で提供されます。macOS では言語環境を自動検出します。
- **プログラミングの知識は不要。** 編集者は `Make Newsletter.bat`（Windows）または `Make Newsletter.command`（macOS）をダブルクリックするだけです。入力するのは号数と Word ファイル名の 2 点のみで、操作はそれだけで完了します。

## 主な利用者

本ツールは、名古屋大学大学院医学系研究科の四半期ニュースレター編集担当者を主な対象としていますが、ツールは**自由にフォークしてご利用いただけます**。同様の課題を抱える他機関の場合、`scripts/config.py` のロゴ・研究科長写真・配色を差し替え、ご自身の GitHub リポジトリを指定するだけで、自部局のブランドに合わせたニュースレター作成環境を整えていただけます。MIT ライセンスでは名古屋大学の商標資産（ロゴ、印章、「MERIDIAN」のワードマーク）は明示的に対象外としていますので、フォークの際にこれらを継承する心配はありません。

**想定される導入先：**

- 大学の各部局（医学・理工・人文系）の学内向けニュースレター

- 編集担当者は非技術者で、Word の下書きから「コピー＆ペーストせずにメールとして体裁よく仕上げたい」というニーズがある組織

## セットアップ（初回のみ・所要約 15 分）

以下の 4 ステップを順番に実施してください。途中の手順は飛ばさないでください。

### ステップ 1 — 無料の GitHub アカウントを作成

1. <https://github.com/signup> にアクセスします。
2. ユーザー名、メールアドレス、パスワードを入力して登録を完了します。
3. 登録された GitHub のユーザー名を、本ツールの保守担当者（このツールをご紹介した担当者、または研究科の総務係）までメールでご連絡ください。写真をアップロードするための書き込み権限を付与いたします。原則として 1 営業日以内にご返信します。**返信が届くまでは、ステップ 2 に進まずお待ちください。**

> **GitHub について。** 本ツールの保管場所です。ご自身のアカウントにはニュースレター用の写真をアップロードする権限を付与しますが、GitHub の操作を覚える必要はありません。すべてツールが自動で処理します。

> **勤務先 PC でソフトのインストールが制限されている場合。** ステップ 2 と 4 では、GitHub Desktop と Python のインストールに管理者権限が必要です。情報基盤部門（または所属の IT 担当者）に「Python と GitHub Desktop をインストールしてほしい」とご依頼ください。本 README をご提示いただければ、必要な作業内容がすぐに把握できます。

### ステップ 2 — GitHub Desktop をインストール

1. <https://desktop.github.com> にアクセスし、**Download for Windows**（または **macOS**）をクリックします。
2. インストーラを実行します。設定はすべて初期値のままで問題ありません。
3. GitHub Desktop が起動したら **Sign in to GitHub.com** をクリックします。ブラウザが開き、GitHub Desktop の認証を求められますので **Authorize** をクリックします。ブラウザでの処理が終わると自動的に GitHub Desktop に切り替わりますので、GitHub Desktop の画面に戻って次のステップへお進みください。

### ステップ 3 — ツールをダウンロード（クローン）

1. GitHub Desktop のメニューから **File → Clone repository…** をクリックします。
2. **URL** タブをクリックし、以下のアドレスを貼り付けます。
   ```
   https://github.com/BasileChretien/Newsletter-graduate-school-medicine.git
   ```
3. **Local path** で **Choose…** をクリックし、**ドキュメント**（または覚えやすい場所）を選択します。
4. **Clone** をクリックします。数秒後に PC に `Newsletter-graduate-school-medicine` というフォルダが作成されます。**毎号、このフォルダを使用します。**

> **次回 github.com を見るときの注意。** GitHub のページには、緑色の **Code** ボタンから **Download ZIP** を選べる項目があります。**こちらはご利用にならないでください。** ZIP から展開した場合、写真のアップロード機能が動作せず、受信者の画面では画像のリンク切れアイコンが表示されてしまいます。必ず **GitHub Desktop**（このステップ 3 の手順）からお取得ください。誤って ZIP を展開してしまった場合も、ランチャーが自動で検出し、正しい手順をご案内しますのでご安心ください。最初から正しい手順で進めていただくと、原因究明に数分を費やす手間を省けます。

### ステップ 4 — Python をインストール

Python はツールを動作させるためのプログラムです。

- **Windows：** <https://www.python.org/downloads/> からインストーラをダウンロードして実行します。**重要：** 最初の画面の下にある **「Add Python to PATH」**のチェックボックスに必ずチェックを入れてください（これを忘れるとツールが Python を見つけられません）。チェックを入れたうえで *Install Now* をクリックします。
- **macOS：** Mac には Python が標準で入っていることが多いです。ご心配な場合は、まずステップ 4 を飛ばしてランチャー（`Make Newsletter.command`）をダブルクリックしてみてください。Python が無い場合のみ、ツールが教えてくれます。明示的に確認したい場合は、**ターミナル**（アプリケーション → ユーティリティ → ターミナル）を開き、`python3 --version` と入力して Enter キーを押してください。`3.12.x` のようなバージョン番号が表示されれば完了です。表示されない場合は、Windows と同じ手順で <https://www.python.org/downloads/> からインストールしてください。

これでセットアップは完了です。**この 4 ステップは初回のみで、次号以降は不要です。**

## ニュースレターの作り方（毎号の手順）

### ステップ 1 — Word でテンプレートを開き、正しい名前で保存

`Meridian_Newsletter_Template.docx` をダブルクリックすると Word が開きます。メニューから **ファイル → 名前を付けて保存** を選び、`Make Newsletter.bat` と同じフォルダに**別名で保存**してください。

> ⚠️ **ファイル名は重要です。** 必ず以下の形式で保存してください。
>
> ```
> issue-N.docx
> ```
>
> `N` は号数です。第 3 号なら **`issue-3.docx`**、第 12 号なら **`issue-12.docx`** とします。

この命名ルールにしておくと、ステップ 4 のランチャーがファイル名を自動で補完してくれるので、Enter キーを押すだけで進められます。

### ステップ 2 — 内容を入力

保存したファイルで、以下を行います。

- 題字部の**発行情報**（「VOL. XX | ISSUE NO. XX | MONTH YEAR」）を、実際の巻号と月年に書き換えます。
- **`[Author(s)]`**、**`[Paper Title]`**、**`[Visitor Name]`**、**`[YYYY/MM/DD]`**、**`[Country]`** などの角括弧で囲まれたプレースホルダを、実際の内容に書き換えます。
- グレー表示の「Lorem ipsum」風のダミー段落を、実際のニュースレター本文に差し替えます。
- **節は自由に編集できます。** ツールは 7 節構成のテンプレートで配布されますが、号ごとに名称変更、追加、削除、並び替えが可能です。
  - **節名を変更する場合：** Word で見出し文字を編集するだけです。番号はそのままで構いません。
  - **新しい節を追加する場合：** 追加したい位置の空行にカーソルを置き、「番号」「ピリオド」「半角スペース」「タイトル」の順に入力します（例：`8. Special Feature: Nobel Prize Winner`）。コロン区切り `8:` や `第 8 章 — タイトル` の形式も認識されます。続いて当該行を選択し、*ホーム → スタイル* の **見出し 1** をクリックします（または Windows：*Ctrl+Alt+1*、Mac：*⌘+Option+1*）。
  - **節を削除する場合：** 見出しと、その節に属するすべての内容（段落、箇条書き、表）を選択し、**Delete** キーを押します。
  - **小見出し**（例「Notable Publications」）には Word の **見出し 2** スタイルを使用してください。行を選択し *ホーム → スタイル* の **見出し 2** をクリックします（または *Ctrl+Alt+2* / *⌘+Option+2*）。スタイル指定を忘れた場合でも、ピリオドのない短い太字の見出しなら自動で認識します。

> **テンプレートが破損する心配はありません。** ご自身が作成する `issue-3.docx` は複製であり、元の `Meridian_Newsletter_Template.docx` には変更が加わりません。**複製に不具合が生じた場合は、当該ファイルを削除してテンプレートをもう一度開いてください。** 失われるデータはありません。

> **研究科長のお名前と写真は組み込み済みです**（現任：*勝野雅央 研究科長*）。研究科長が交代された場合は、保守担当者にテンプレートの更新をご依頼ください。

完了したら保存します。

### ステップ 3 — 写真を追加（任意）

> ⚠️ **プライバシーに関する注意。** ニュースレターに挿入した写真はすべて**公開**の GitHub URL（`raw.githubusercontent.com/...`）にアップロードされ、永続的に保存されます。**患者の写真、本人の同意が得られていない顔写真、その他公開ウェブページに掲載できない画像は、絶対に貼り付けないでください。**

**写真は Word ファイルに直接貼り付けてください。** 挿入したい位置にカーソルを合わせ、**挿入 → 画像** からファイルを選択し、角をドラッグしてサイズを調整します。操作は以上です。ツールが自動で検出し、メール上の同じ位置に同じサイズで配置します。

**コツ：**

- Word 上で、メールでの表示サイズに近い大きさに調整します（厳密でなくて構いません。大きすぎる画像は、メールに収まるサイズへ自動で縮小されます）。
- 大きすぎる場合は、Word で角を内側にドラッグしてください。
- どの節にも、好きなだけ写真を追加できます。

> **研究科長の写真と研究科のロゴは標準で組み込み済みです。** ご自身で追加する必要はありません。

> ご参考：写真を一括で追加したい場合は、`drop-images/` フォルダにファイル名規則（`s<節番号>_<順番>_<英数字短名>.jpg`）に沿って配置する方法もありますが、Word に貼り付ける方が簡単ですので、最初は気にしなくて大丈夫です。

### ステップ 4 — ランチャーをダブルクリック

プロジェクトフォルダ内の以下のファイルを**ダブルクリック**します。

- **Windows：** `Make Newsletter.bat`
- **macOS：** `Make Newsletter.command`

黒い背景の小さな画面が開きます（**これは正常です。閉じないでください**）。質問が 2 つだけ表示されます。

```
Issue number / 号数 (例 3): 3
Word file / Wordファイル [issue-3.docx]:        ← Enter キーを押すだけ
```

`3`（または該当する号数）を入力して Enter キーを 2 回押します。初回のみ、ツールが自動でセットアップを行います（約 1 分）。2 回目以降の実行では、待ち時間なくメールの作成が始まります。

### ステップ 5 — 宛先を選んで送信

完了すると、ご利用のメールアプリにニュースレター入りの下書きが表示されます。

- **Outlook デスクトップの場合：** 下書きが開きます。**To: 欄に宛先を入力し、「送信」をクリックするだけです。**
- **その他のメールアプリの場合：** クリップボードにニュースレターが格納されたうえで、新規下書きが開きます。本文欄をクリックして `Ctrl+V`（Mac は `⌘+V`）で貼り付け、宛先を入力して送信してください。

> **重要：** メールはまだ送信されていません。宛先を入力し、内容を確認のうえ、最後にご自身で「送信」ボタンをクリックしてください。

### 宛先リストを保存しておく（任意）

毎号同じ宛先（おおむね 50 名）に送信する場合は、`recipients.example.txt` を `recipients.txt` にコピーし、メールアドレスを 1 行 1 件で記入しておきます。次回以降、Outlook の BCC 欄が自動で入力されます。`recipients.txt` はお使いの PC のみに保存され、GitHub には公開されません。

## よくある質問

**Q. ランチャーをダブルクリックしても何も起こらない、または一瞬で閉じてしまう。**
主な原因は次の 2 点です。
- **Python が未インストール：** ランチャーをダブルクリックしても何も起きない場合、ほとんどは Python が入っていないことが原因です。セットアップのステップ 4（Python のインストール）をもう一度ご確認ください。それでも解決しない場合は、画面を写真に撮って保守担当者にお送りください。
- **macOS のみ：** macOS には初回のみ実行権限の付与が必要です。ターミナルで該当フォルダに移動し、`chmod +x "Make Newsletter.command"` を一度実行してください。再度ダブルクリックすれば動作します。

**Q.「ERROR: file not found」と表示される。**
入力された Word ファイルがプロジェクトフォルダ内に見つかりません。`issue-3.docx`（または指定したファイル名）を `Make Newsletter.bat` と同じフォルダに移動してから、ランチャーを再実行してください。

**Q. 研究科長の写真や研究科ロゴがプレビューに表示されない。**
ランチャー（または `all` コマンド）から実行してください。この手順でのみ、写真が Web 上に公開されます。それでも表示されない場合は、ブラウザを再読み込みしてください。

**Q. プレビューに画像の代わりに壊れたアイコンが表示される。**
写真がまだ公開 Web にアップロードされていない可能性があります。ランチャーをもう一度実行してください（毎回、写真は自動でアップロードされます）。続いてプレビューを更新します。`drop-images/` フォルダを使用された場合は、ファイル名が半角小文字で「s（節番号）_（順番 2 桁）_（短い英数字）.jpg」の形式になっているかご確認ください（例：`s3_01_lab.jpg`／NG 例：`S3-01-lab.jpg`、`lab photo.jpg`。大文字、ハイフン、空白は使用できません）。

**Q. もう一度作り直したい。**
ランチャーをもう一度ダブルクリックし、同じ号数を入力してください。前回の出力ファイルは自動的に上書きされますので、そのまま再実行いただけます。

**Q. テンプレートの色・フォント・タイトルを変更したい。**
これらは号ごとの統一感を保つため固定にしています。デザイン変更が必要な場合は、保守担当者（このツールをセットアップした方）にご相談ください。

**Q. 新しい節を追加したい。**
追加できます。Word で追加したい位置の空行にカーソルを置き、「番号」「ピリオド」「タイトル」の順に入力してください（例：`8. Special Feature: Nobel Prize`）。続いて当該行を選択し、*ホーム → スタイル* の **見出し 1** をクリックします（または *Ctrl+Alt+1* / *⌘+Option+1*）。コードの修正は不要です。

**Q. 節や小見出しを削除したい。**
見出しと、その節に属するすべての内容（段落、箇条書き、表）を選択し、**Delete** キーを押してください。ツールは削除された節を自動的にスキップします。

**Q. テンプレートを壊してしまわないか不安。**
ご安心ください。ご自身が作成する `issue-3.docx` は複製であり、元の `Meridian_Newsletter_Template.docx` には変更が加わりません。**複製に不具合が生じた場合は、当該ファイルを削除してテンプレートをもう一度開いてください。** 失われるデータはありません。

**Q. メールファイルの保存先はどこですか。**
`dist/` フォルダの中です。第 3 号の場合は `dist/issue-3.html` に保存されます。いつでもダブルクリックして開けます。

**Q. ドロップフォルダの写真はどこに保存されますか。**
第 N 号の場合は `assets/issue-N/` に保存されます。同時に GitHub にもアップロードされ、公開 URL から参照可能になります。

**Q. どのメールアプリが使用されますか。**
お使いの PC で `mailto:` リンクの既定に設定されているアプリです。確認したい場合は、保守担当者に「このツールでどのメールアプリが使われるか」とお問い合わせください。
- Windows：設定 → アプリ → 既定のアプリ → メール
- macOS：メールアプリ → 環境設定 → 一般 → デフォルトメールアプリ

**Q. 既定が Outlook なのに、ブラウザが開いてしまう。**
Outlook が起動していない、または直近の Office 更新で連携の挙動が変わった場合に発生します。Outlook をいったん起動してから、ランチャーをもう一度ダブルクリックしてください。多くの場合これで解決します。それでもブラウザが開いてしまう場合は、保守担当者にご相談ください。

**Q. メールは開いたが、本文にニュースレターが入っていない（本文が空）。**
Outlook 以外のメーラー向けの動作になっています。ニュースレターはクリップボードに格納済みですので、本文欄をクリックし `Ctrl+V`（macOS は `⌘+V`）で貼り付けてください。

**Q. ランチャーが英語表示なのはなぜですか。**
Windows の技術的な制約により、ランチャー画面の案内文は英語のままになっています。ニュースレター本体および本日本語マニュアルは日本語ですので、ご安心ください（補足：Windows の `cmd.exe` はバッチファイルを OEM コードページ（日本語環境では cp932）として読み込むため、UTF-8 の日本語を含めると文字化けし、起動エラーの原因となります）。なお macOS の `Make Newsletter.command` は UTF-8 を正しく扱えるため、日本語表示が利用可能です。

**Q. macOS の `Make Newsletter.command` で日本語が四角（□）で表示される。**
ターミナルのプロファイル設定で、フォントを **MS Gothic** などの日本語対応フォントに変更してください。

**Q. 内容のわかりにくいエラーメッセージが表示された。**
赤字部分を画面ごと撮影、または文字をコピーのうえ、保守担当者にお送りください。原因の特定は担当者側で行いますので、内容を理解する必要はありません。多くのエラーには原因が明示されています（例：「画像のファイル名が命名規則に従っていません」）。

**Q. 受信者から「メール内の画像が表示されない」と連絡があった。**
画像は GitHub の `raw.githubusercontent.com` から配信されており、一部の企業・病院のメールフィルタは、本文は通過させても、このドメインからの画像のみを隔離・削除する場合があります。名古屋大学の受信者からこの現象が報告された場合は、保守担当者に **GitHub Pages ミラー** の設定をご依頼ください。同一ファイルを `<ユーザー名>.github.io/<リポジトリ名>/assets/...` から配信できるようになります（配信ネットワークが異なるため、フィルタを通過しやすくなります）。設定が完了するまでの暫定対応として、受信者側で表示されない画像アイコンをクリックすると画像を直接開けます。

**Q. BCC で同時送信できる宛先数の上限はどの程度ですか。**
名古屋大学のメールサーバを含め、多くの教育機関では 1 通あたり概ね 50 件程度の BCC が運用上の目安となっています。これを超えると、サーバ側で大量送信と判定され、配送遅延・隔離の対象となる場合があります。配信先がそれを上回る場合は、`recipients.txt` を 50 件以下に分割し、複数回に分けて送信してください（上限値はメールサーバ側で制御されており、本ツールでは制限を設けていません）。さらに大規模な配信が必要な場合は、情報基盤部門にメーリングリストの発行をご相談ください。

**Q. 迷惑メールフィルタにブロックされませんか。**
送信元の信頼性は、ツールではなくお使いの大学のメールサーバ側の設定によって決まります。`@med.nagoya-u.ac.jp` から送信する場合は、大学の SPF / DKIM / DMARC 設定が自動的に適用されるため、追加の設定は不要です。個人の Gmail / Outlook アカウントから送信した場合、企業向けフィルタで評価が下がる可能性があります。

**Q. メールを印刷すると、ヘッダー部（題字）の見え方が画面と異なる。**
これは仕様です。受信者が印刷ボタンを押したときだけ、インク節約のため上部のヘッダー部分が白黒になります。画面で読むときの見た目は変わりませんので、ご安心ください。
